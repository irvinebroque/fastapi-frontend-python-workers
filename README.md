# FastAPI Frontend on Cloudflare Python Workers

This repository shows the Cloudflare Workers version of the FastAPI frontend tutorial with a modern JavaScript frontend:

1. Build a React frontend with Vite and Kumo UI into a static `dist/` directory.
2. Serve that frontend from the same origin as the API.
3. Keep normal FastAPI path operations for `/api`.
4. Deploy the whole thing to Cloudflare with Python Workers.

In the FastAPI tutorial, `app.frontend("/", directory="dist")` makes FastAPI serve the built frontend. On Cloudflare Workers, the equivalent production shape is to let Cloudflare Static Assets serve `dist/` and let the Python Worker run only for API routes. That keeps the FastAPI developer experience while avoiding Python Worker invocations for every image, CSS file, or browser navigation.

The important distinction: FastAPI powers the backend. Cloudflare serves the built frontend assets.

## Live Example

- App: https://fastapi-frontend-python-workers.roundtrip.workers.dev/
- API: https://fastapi-frontend-python-workers.roundtrip.workers.dev/api
- Docs: https://fastapi-frontend-python-workers.roundtrip.workers.dev/api/docs

## What Runs Where

| Request | Handler |
| --- | --- |
| `/` | Cloudflare Static Assets serves `dist/index.html` |
| `/assets/...` | Cloudflare Static Assets serves built JS/CSS |
| `/dashboard` | SPA fallback serves `dist/index.html` |
| `/api` | FastAPI inside `src/entry.py` |
| `/api/docs` | FastAPI Swagger UI |
| `/api/items/42?q=demo` | FastAPI path operation |

The routing lives in `wrangler.jsonc`:

```jsonc
"assets": {
  "directory": "./dist/",
  "binding": "ASSETS",
  "not_found_handling": "single-page-application"
}
```

Cloudflare serves matching static assets first. Requests that do not match an asset,
including `/api`, fall through to the Python Worker in `src/entry.py`.

`frontend/` is a Vite + React app using Kumo UI components from `@cloudflare/kumo`. `src/entry.py` is a FastAPI app adapted to Cloudflare's Python Worker ASGI bridge. `pylock.toml` is generated by `pywrangler` for the Pyodide package set that deploys to Workers.

## Frontend Stack

- Vite 8
- React 19
- Kumo UI (`@cloudflare/kumo`)
- Kumo standalone styles, so no Tailwind setup is required for this small example

Kumo is React-based, so this repo uses React as the framework layer. The visible buttons, inputs, badges, cards, and tabs come from Kumo.

## FastAPI Worker Entry Point

```python
import asgi
from fastapi import FastAPI
from workers import WorkerEntrypoint

app = FastAPI(
    docs_url="/api/docs",
    openapi_url="/api/openapi.json",
)


@app.get("/api")
async def read_root():
    return {"message": "Hello from FastAPI on Cloudflare Python Workers"}


class Default(WorkerEntrypoint):
    async def fetch(self, request):
        return await asgi.fetch(app, request, self.env)
```

## Prerequisites

- Node.js and npm
- `uv`

Python Workers are currently beta, so `wrangler.jsonc` includes the required `python_workers` compatibility flag.

## Local Development

Install dependencies:

```bash
npm install
uv sync
```

Run the full app locally:

```bash
npm run dev
```

Open:

- `http://localhost:8787/`
- `http://localhost:8787/api`
- `http://localhost:8787/api/docs`

The `dev` script builds the frontend first, then starts `pywrangler dev` so the local runtime matches deployment.

For framework-style frontend iteration with Vite hot reload, use two terminals:

```bash
npm run dev:worker
```

```bash
npm run dev:frontend
```

Then open `http://localhost:5173/`. Vite proxies `/api` to the local Python Worker on `http://localhost:8787`.

## Build and Validate

```bash
npm run build
npm run check
```

`npm run check` builds `dist/` and runs a Cloudflare deploy dry run.

## Deploy

Log in once:

```bash
npx wrangler login
```

Deploy:

```bash
npm run deploy
```

After deploy, Wrangler prints the `workers.dev` URL. The live app should serve the frontend at `/` and the FastAPI docs at `/api/docs`.

## Why This Is Not `app.frontend()`

The FastAPI tutorial is exactly right for a Python server that owns both the API and static file serving. On Workers, Cloudflare already has first-class static asset serving and caching at the platform layer. So this repo maps the tutorial's idea like this:

| FastAPI tutorial | Cloudflare Workers version |
| --- | --- |
| `npm run build` creates `dist/` | same |
| `app.frontend("/", directory="dist")` serves files | `assets.directory = "./dist/"` serves files |
| FastAPI routes win before frontend fallback | unmatched paths like `/api` fall through to the Python Worker |
| `fallback="index.html"` for an SPA | `not_found_handling = "single-page-application"` |

That gives people coming from FastAPI the same app shape with Cloudflare's deployment model.

If you specifically want to prove FastAPI itself can serve frontend assets with `app.frontend()`, that is a different example. For Cloudflare Workers, this repository chooses the platform-native approach: static assets at Cloudflare's asset layer, FastAPI at the API layer.
